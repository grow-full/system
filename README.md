# 우왕이와 떠나는 여행

> 충북대학교 마스코트 우왕이를 키우며 가상 여행, 공부, 캠퍼스 산책을 즐기는 웹앱

시스템 분석 및 설계 프로젝트의 발표용 README입니다. 현재 저장소의 구현 내용을 바탕으로 기능과 설계 의도를 정리했으며, 마지막에 PPT 구성과 시연 순서를 담았습니다.

## 1. 프로젝트 소개

사용자는 우왕이를 부화시키고 밥을 주거나 놀아 주면서 성장시킵니다. 함께 여행을 떠나 기념품과 의상을 모으고, 여행 화면을 집중 타이머로 활용할 수 있습니다. 캠퍼스 산책과 미니게임에서 얻은 보상은 다시 돌보기와 여행에 사용됩니다.

**발표 소개 문장**

“우왕이와 떠나는 여행은 학교 마스코트를 직접 키우면서 여행과 캠퍼스 탐험을 즐기고, 공부 시간까지 기록할 수 있는 웹앱입니다.”

## 2. 기획 배경과 목표

아래 내용은 구현된 기능을 설명하기 위한 기획 관점입니다. 사용자 조사나 효과 측정 결과를 뜻하지 않습니다.

| 기획 방향 | 서비스에 반영한 방식 |
|---|---|
| 학교 마스코트와 친밀감을 만들기 | 돌보기, 대화, 성장, 의상과 방 꾸미기 |
| 반복해서 방문할 이유 만들기 | 상태 변화, 여행 기록, 도감과 수집 보상 |
| 공부 시간을 즐겁게 보내기 | 가상 이동 화면과 집중 타이머 결합 |
| 캠퍼스를 탐색하는 경험 제공하기 | Street View 산책, 장소 도장, 숨은 친구 |
| 설치 없이 쉽게 접근하기 | 브라우저에서 실행하는 반응형 웹앱 |

## 3. 핵심 사용자 흐름

```text
우왕이 부화 → 돌보기와 성장 → 게임·산책으로 코인 획득
                                    ↓
                        여행 계획 → 발권 → 탑승 → 도착
                                    ↓
                        의상·기념품·여권 도장 수집
                                    ↓
                             꾸미기와 다음 여행

별도 활용: 여행의 집중 모드로 공부 시간 기록 → 누적 시간 보상
```

각 기능이 코인, 경험치, 의상, 기념품을 통해 연결되도록 구성했습니다.

## 4. 주요 구현 기능

### 4.1 우왕이 키우기

- 알 → 아기 → 어린이 → 어른 순서로 성장합니다. 어린이는 레벨 3, 어른은 레벨 5에 도달하면 됩니다.
- 배고픔, 행복, 질병, 청결, 수면 상태를 관리합니다.
- 밥·간식·약에는 코인을 사용하며, 청소·씻기·놀아주기 등을 제공합니다.
- 돌봄 실수와 여행·게임 기록에 따라 어른 모습이 5가지로 나뉩니다.
- 정해진 주제나 직접 입력한 말에 규칙 기반으로 반응합니다. 생성형 AI 대화 기능은 아닙니다.
- 여행 의상과 기념품으로 캐릭터와 방을 꾸밀 수 있습니다.
- 경영정보학과 과목의 수업 듣기, 공부하기, 복습 퀴즈와 수강 기록을 제공합니다.

### 4.2 가상 여행

- 국내 7곳, 해외 14곳으로 총 21개 여행지를 제공합니다.
- 비행기, KTX, 고속버스, 배 중 교통수단을 선택합니다.
- 출발지, 목적지, 좌석 등급과 좌석 번호를 고르고 표를 발권합니다.
- 거리·교통수단·등급에 따라 코인 요금을 계산하며 첫 여행은 무료입니다.
- 현재 시각과 교통수단에 맞춰 창밖 풍경이 달라집니다.
- 도착하면 여행 기록을 남기고, 첫 방문 보상으로 의상과 기념품을 받습니다.

가상 여행 기능이며 실제 교통편 예약이나 결제 시스템과 연동하지 않습니다. 기본 이동 시간은 대략적인 값이고 사용자가 조절할 수 있습니다.

### 4.3 집중 모드

- 여행 화면을 공부 타이머로 활용합니다.
- 화면을 보고 있는 동안 시간을 누적하고, 다른 탭이나 창으로 이동하면 일시 정지합니다.
- 돌아오면 타이머가 이어지며 누적 집중 시간에 따라 공부 코스튬 6종을 지급합니다.

브라우저의 화면 표시 여부와 포커스를 기준으로 계산하므로 사용자의 실제 학습 여부를 판별하는 기능은 아닙니다.

### 4.4 미니게임 7종

| 게임 | 주요 방식 |
|---|---|
| 특산품 받기 | 떨어지는 먹거리를 받고 장애물 피하기 |
| 짝 맞추기 | 카드 16장에서 같은 그림 8쌍 찾기 |
| 여행 퀴즈 | 여행지 관련 5문제 풀기 |
| 기념품 타일 매치 | 같은 기념품 3개 모으기 |
| 장애물 피하기 | 점프하며 장애물을 피하고 별 모으기 |
| 짐 싸기 블록 퍼즐 | 블록을 놓아 가로·세로 줄 완성하기 |
| 특산품 3매치 | 인접한 칸을 바꿔 같은 먹거리 연결하기 |

게임 결과에 따라 코인과 경험치를 받고, 이를 돌보기와 여행에 활용합니다.

### 4.5 캠퍼스 산책

- Google Maps JavaScript API의 Street View로 충북대학교 캠퍼스를 탐색합니다.
- 출발 장소와 의상을 고르고 방향키 또는 화면 버튼으로 이동합니다.
- 지도와 가까운 장소 목록으로 위치를 확인합니다.
- 장소별 감상과 배경음, 걸음과 시간에 따른 보상을 제공합니다.
- 장소 도장과 숨은 친구 5명을 수집하고, 산책 종료 시 활동 요약을 확인합니다.

걸음과 거리는 가상 이동을 바탕으로 한 게임 내 기록이며 실제 보행 측정값이 아닙니다.

### 4.6 커뮤니티와 계정 저장

- 여행 꿀팁 작성, 여행지·분류별 필터, 정렬, 좋아요와 댓글을 제공합니다.
- 커뮤니티는 Supabase 계정 저장을 우선 사용하고, 설정이 없으면 로컬/Firebase 저장을 지원합니다.
- Supabase 기반 아이디·비밀번호 로그인과 계정별 진행 저장을 구현했습니다.
- 여러 기기의 진행은 최근 직접 플레이한 시각을 기준으로 비교합니다.

**현재 연결 방식:** Supabase 설정이 있으면 기존 로그인 계정으로 커뮤니티를 이용합니다. [커뮤니티 SQL](system/sql/community.sql)을 Supabase SQL Editor에서 실행해야 공유 저장이 동작합니다. 설정이 없으면 기존 로컬/Firebase 방식을 사용합니다. 실제 가입·동기화와 서버 정책은 발표 전에 접속해서 확인해야 합니다.

## 5. 화면과 디자인

- 크림색과 버건디를 중심으로 한 레트로 픽셀 UI를 사용합니다.
- 한글 글꼴은 갈무리를 사용하고 캐릭터는 PNG 스프라이트와 애니메이션으로 표현합니다.
- PC에서는 왼쪽 메뉴, 가운데 콘텐츠, 오른쪽 보조 패널로 구성합니다.
- 가로 900px 미만에서는 모바일 배치로 전환합니다.
- Web Audio API로 효과음과 배경음을 합성합니다.

## 6. 기술 구성과 설계

| 구분 | 사용 기술 | 역할 |
|---|---|---|
| 화면 | HTML, CSS, JavaScript | 화면 구성, 반응형 스타일, 이벤트 처리 |
| 기본 저장 | localStorage | 캐릭터·재화·기록과 로컬 게시글 저장 |
| 계정 | Supabase Auth | 회원가입과 로그인 |
| 클라우드 저장 | Supabase 데이터베이스 | 계정별 게임 진행 저장·불러오기 |
| 공유 게시판 | Supabase 데이터베이스 / Firebase Firestore | 계정 기반 게시글·댓글·좋아요 저장, 기존 Firebase 방식 지원 |
| 지도 | Google Maps JavaScript API | Street View와 위치 지도 |
| 사운드 | Web Audio API | 효과음과 환경음 합성 |

별도 프런트엔드 프레임워크나 빌드 과정 없이 정적 파일로 실행합니다. 외부 서비스 연결은 브라우저에서 각 SDK와 API를 이용하는 구조입니다.

```text
index.html + style.css
         ↓
app.js: 초기화, 탭 전환, 1초 주기 갱신
         ↓
Pet / Travel / Focus / Games / Walk / Community
         ↓
state.js: 공통 상태, 성장·돌봄 규칙, 저장·불러오기
         ↓
localStorage ←→ Cloud 모듈 ←→ Supabase

Community ←→ Supabase (설정이 없으면 로컬 저장 또는 Firestore)
Walk      ←→ Google Maps / Street View
```

핵심 설계 포인트는 다음과 같습니다.

1. **기능별 파일 분리:** 돌보기, 여행, 게임, 산책 등을 각각의 모듈로 나눴습니다. 다만 전역 상태와 함수를 공유하므로 스크립트 로딩 순서에 의존합니다.
2. **시간 기반 상태 처리:** 기본 돌봄은 마지막 갱신 시각부터 경과한 시간을 분 단위로 반영합니다. 집중 모드는 화면을 보는 시간을 별도로 계산합니다.
3. **저장 데이터 호환:** 저장 데이터를 불러올 때 기본값과 합치고 일부 이전 형식을 보정합니다.
4. **연결 가능한 저장소:** 로컬 저장을 기본으로 두고, 설정에 따라 계정 저장과 공유 게시판을 연결합니다.

## 8. 실행 방법

저장소 루트에서 아래 명령을 실행합니다.

```powershell
cd system
python -m http.server 8000
```

Python이 없는 Windows 환경에서는 다음 명령을 사용할 수 있습니다.

```powershell
cd system
powershell -ExecutionPolicy Bypass -File serve.ps1
```

브라우저에서 `http://localhost:8000`에 접속합니다. 서버는 `Ctrl + C`로 종료합니다. 지도 기능은 로컬 서버로 실행해야 하며 외부 서비스와 글꼴을 사용하려면 인터넷 연결이 필요합니다.

지도 키는 저장소에 포함되어 있습니다. 기존 설정 문서상 허용 주소는 `http://localhost:8000/*`와 `https://grow-full.github.io/*`입니다. 실제 제한은 Google Cloud 설정에 따라 적용됩니다.

자세한 실행 안내와 Firebase·Supabase 설정은 [상세 README](system/README.md)를 참고하세요.

## 누적 이용자 수

메뉴의 코인·계정 버튼 근처에 **누적 이용자 N명**을 표시합니다. Supabase SQL Editor에서 [이용자 집계 SQL](system/sql/visitors.sql)을 실행한 뒤 변경 코드를 기존 방식으로 배포합니다. 커뮤니티 SQL과 별개이며 기존 게임 진행에는 영향을 주지 않습니다.

- 공개 HTTPS 사이트에 접속한 브라우저의 첫 방문을 로그인 여부와 관계없이 집계합니다. 같은 브라우저의 재방문·새로고침·로그아웃·게임 초기화는 중복 집계하지 않습니다.
- localhost 개발 접속은 조회만 합니다. 브라우저 저장이 차단된 경우에도 조회만 합니다.
- 다른 기기·브라우저, 시크릿 창, 브라우저 저장소 삭제 후 방문은 별도로 집계될 수 있습니다. 실제 사람의 정확한 수나 로그인 계정 수는 아닙니다.
- 접속 시, 탭으로 돌아올 때, 화면이 열린 동안 1분 간격으로 갱신합니다. 서버 연결이 실패하면 ‘확인 불가’로 표시합니다.
- 익명 UUID와 첫 방문 시각만 저장하며 일반 사용자에게 원본 방문자 목록을 공개하지 않습니다.
- 기능 적용 이후부터 집계하며 과거 방문은 소급하지 않습니다. 공개 API이므로 자동화된 허위 방문을 완전히 방지하는 분석 도구는 아닙니다.

## 9. PPT 구성안 — 10장, 약 7~10분

| 장 | 제목 | 슬라이드에 넣을 내용 | 추천 화면 |
|---|---|---|---|
| 1 | 우왕이와 떠나는 여행 | 프로젝트명, 한 줄 소개, 팀명·발표자 | 우왕이 메인 화면 |
| 2 | 기획 배경과 목표 | 마스코트 친밀감, 반복 방문, 공부와 탐험 | 핵심 목표 3~4개 |
| 3 | 서비스 전체 흐름 | 돌보기 → 보상 획득 → 여행 → 수집과 꾸미기 | 사용자 흐름도 |
| 4 | 우왕이 키우기 | 상태 관리, 성장 분기, 수업과 방 꾸미기 | 방·도감·수업 화면 |
| 5 | 여행과 집중 모드 | 교통수단, 좌석, 발권, 화면 이탈 시 정지 | 발권·이동 화면 |
| 6 | 게임과 보상 | 게임 7종, 코인과 경험치의 사용처 | 게임 목록과 플레이 |
| 7 | 캠퍼스 산책 | Street View, 장소 탐색, 친구와 도장 | 산책·지도·종료 요약 |
| 8 | 기술 구조 | 기능별 모듈, 공통 상태, 로컬·클라우드 저장 | 구조도 |
| 9 | 구현 결과와 한계 | 구현 범위, 현재 연결 설정, 검증할 항목 | 기능 요약 표 |
| 10 | 향후 개선과 마무리 | 보안, 구조 개선, 사용자 테스트 계획 | 개선 과제 3개 |

실제 팀원별 역할, 개발 기간, 사용자가 직접 확인한 테스트 결과는 발표 전에 추가합니다. 저장소만으로 확정할 수 없는 기여도나 성과 수치는 넣지 않았습니다.

## 10. 발표 시연 순서 — 약 3분

1. **우왕이 방:** 캐릭터를 보여 주고 돌보기와 의상 변경을 시연합니다.
2. **여행 계획:** 교통수단·목적지·좌석을 고른 뒤 표를 발권합니다.
3. **집중 모드:** 짧은 시간으로 탑승하고 다른 창으로 이동해 일시 정지를 보여 줍니다.
4. **미니게임:** 한 가지 게임을 짧게 플레이해 보상 구조를 설명합니다.
5. **캠퍼스 산책:** 준비 화면을 거쳐 Street View와 장소 지도를 보여 줍니다.
6. **저장 방식:** 로컬 저장을 설명하고, 사전에 확인한 경우에만 로그인·동기화를 시연합니다.

시연 전에는 캐릭터가 깨어 있고 배고프거나 아프지 않은지, 여행에 쓸 코인이 있는지 확인합니다. 여행과 수업 등 진행 중인 활동은 다음 시연에 맞춰 종료하고, 지도 로딩과 소리는 미리 점검합니다. 인터넷이 불안정할 경우를 대비해 주요 화면 캡처를 준비합니다.

## 11. 현재 한계와 향후 개선

| 현재 확인되는 제약 | 향후 개선 방향 |
|---|---|
| 전역 상태와 스크립트 로딩 순서에 의존 | ES Modules 도입과 의존성 정리 |
| Supabase 커뮤니티 연동 코드와 권한 SQL을 준비했으며 서버 적용·실사용 검증이 필요함 | SQL 적용 후 두 계정에서 공유 조회·작성자 삭제 권한·좋아요 동기화 검증 |
| 기기 시각 기반으로 저장 충돌을 비교 | 서버 기준 버전과 동시 저장 충돌 처리 보강 |
| 아이디를 내부 이메일로 변환하며 이메일 복구 기능이 없음 | 계정 복구 방식 설계 |
| 지도·계정 기능이 외부 서비스 설정과 네트워크에 의존 | 오류 안내와 연결 실패 대응 개선 |
| 자동 검증과 사용자 평가 결과가 이 문서에 없음 | 주요 흐름 테스트, 모바일·접근성 점검, 사용자 피드백 수집 |

발표에서는 **구현한 기능**, **현재 외부 서비스 연결 상태**, **향후 개선 계획**을 구분해 설명합니다. 이 문서는 코드와 기존 문서를 기준으로 작성했으며 전체 기능의 브라우저 실행 검증 결과를 뜻하지 않습니다.
